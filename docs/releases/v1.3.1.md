# v1.3.1：实机确认后的正式版

发布日期：2026-11-23（北京时间）。目标：ESP32-S2 mini / S2FNR2，4 MB flash、2 MB PSRAM。
本版作为最新正式版发布，整合 v1.3.0 的修复和已实机验证的面板阶段日志。
用户确认当前设备测试没有问题；具体已记录结果与后续回归项目见下文。

## 修复与优化

- **DNS 与规则**：修正自定义规则被主表 Bloom 跳过的问题，Bloom 位点与构建器一致；
  增加 16 项保守正响应 TTL 缓存、可配置主备上游和严格的应答来源 / ID / 问题校验。
- **排行**：固定 12 项 Space-Saving 支持新热点替换，保存完整域名；网页说明计数上界和误差。
- **主循环响应**：面板复位、上电、分行发送、刷新和断电使用状态机；每次最多发送两行。
  WiFi 连接与恢复由主循环轮询，远程列表下载移至后台并由主循环安装。
- **失败保护**：面板 BUSY 阶段 45 s、单次整帧 120 s 上限，失败退避后有限重试；
  配置与规则使用临时文件替换，失败保留旧数据。
- **上传与 HTTPS**：上传开始前验证认证和 CSRF，OTA 校验长度、芯片、镜像与可选 SHA-256；
  失败不重启。HTTPS 要求 CA 与对时，保留明确的进度、空间和错误信息。
- **本次新增**：保留 `[EPD-DIAG]` 阶段切换日志，记录阶段耗时、BUSY 和发送行数，
  便于复核软件复位或面板恢复。只在状态切换时打印，不在逐字节 SPI 或 DNS 查询路径打印。

原 64 行 / 12,288 字节分带、bit-bang 字节时序和上下半屏行窗公式保持实测逻辑。
原版曾有约 148 ms 的短 BUSY；后续两轮实测均恢复约 15.35 s 完整刷新。
没有独立定位该现象的根因，因此本版不把阶段日志描述为已确定的时序修复。

## 验证结果

完整烧写、LittleFS / PSRAM 加载、103,366 条规则、4/4 拦截与 3/3 放行自检、
管理员密码持久化及屏幕方向 / 上下半区已检查。阶段日志应用上传后和软件复位后
各完成两帧刷新，整帧约 17.1 s；用户先确认刷新正常，2026-11-23 再确认当前测试没有问题。

正式发布前重新编译应用、LittleFS 和合成镜像，运行原生 C++、构建器、失败保护、
打包脚本及字形回归。结果和产物摘要见[构建记录](../BUILD-VERIFICATION.md)，
真机详细数据见[实机记录](../HARDWARE-TEST-2026-11-21.md)。
用户总体反馈没有附每个测试项目的数据；未逐项记录的无线压力、TLS / OTA 失败注入和
24 / 72 h 长跑继续保留在[回归清单](../HARDWARE-TEST-CHECKLIST.md)。

## 下载与升级

从同一 `v1.3.1` 页面下载匹配附件，并核对 `SHA256SUMS.txt`。

|附件|用途|
|---|---|
|`firmware.bin`|已有设备 Web OTA 或仅烧写应用，保留文件系统配置|
|`firmware-merged.bin`|首次部署 / 完整重新初始化，从 `0x0` 烧写，覆盖配置|
|`littlefs.bin`|完整文件系统；烧写会覆盖现有密码、WiFi 和规则配置|
|`blocklist.bin`|单独更新默认主规则表|
|`esp32s2-flash-v1.3.1.zip`|分区烧写组件及命令说明|
|`esp32s2-debug-v1.3.1.zip`|同批构建 ELF、map、应用目标文件和构建配置|
|`release-docs-v1.3.1.zip`|部署指南、构建 / 实机记录、署名及主要上游许可全文|
|`release-metadata.json` / `SHA256SUMS.txt`|源码提交、工具版本、实测对应关系、文件大小与摘要|

已有设备优先只升级 `firmware.bin`，串口应用偏移为 `0x10000`；不要运行 `uploadfs`。
Web OTA 只接收应用镜像。已运行本次实测应用的设备无需为了正式版标记重新初始化。
首次部署没有预置管理员凭据：启动生成随机密码，通过 115200 串口读取，用户为 `admin`。
部署、编译和恢复命令见[GUIDE.md](../../GUIDE.md)。
